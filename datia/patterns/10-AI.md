Patron de funcionamiento de AI (Inteligencia Artificial)
======================================================
Este patrón define la arquitectura, flujo y componentes del cerebro del sistema Datia.

1. Arquitectura Backend (Cerebro)
---------------------------------
El núcleo reside en `datia/services/ai/`.

### 1.1 Facade Principal (`ai_service.py`)
Clase `IAService`. Actúa como punto de entrada único para todas las consultas.
- **Responsabilidad**: Orquestar la detección de idioma, enrutamiento de intenciones y formateo.
- **Método Principal**: `generate_answer(question, empresa, ejercicio, ...)`
- **Flujo**:
  1. Extracción de parámetros (Año, Top N).
  2. Detección de idioma (`LanguageService`).
  3. Enrutamiento (`IntentRouter`).
  4. Ejecución de Handler.

### 1.2 Enrutamiento de Intenciones (`router.py`)
Clase `IntentRouter`. Decide qué "habilidad" de la AI debe responder.
- **Mecanismo**: Usa distancias vectoriales (Embeddings) para clasificar la pregunta del usuario.
- **Intents Soportados**:
  - `sql_query`: Consultas de negocio que requieren base de datos.
  - `general_chat`: Preguntas conversacionales ("Hola", "Qué eres").
  - `training`: Solicitudes de enseñanza explícita.
  - `deep_dive`: Análisis profundos de respuestas previas.

### 1.3 Generación de SQL (`query_builder.py`)
Transforma lenguaje natural en SQL seguro compatible con Postgres.
- **Seguridad**: Solo permite SELECT. Usa esquemas mapeados (`DataSource`, `DataField`).
- **Chain-of-Thought**: Genera un JSON intermedio con el razonamiento antes de escribir el SQL.
- **RAG**: Inyecta contexto de negocio (definido en `Auto entreno.md`) en el System Prompt.

- Se prueban los casos: “Top 20 clientes en mayo 2025”, “Qué cliente compra menos en 2025”, “Margen por cliente del último trimestre 2025”.

### 1.4 Generación de Texto (`ollama_service.py`)
Wrapper para la comunicación con el modelo local Ollama (Llama 3).
- **Streaming**: Soporta generación token a token (aunque el frontend actual usa respuesta completa).
- **Contexto**: Inyecta `datia_businesscontext` (Postgres) en cada prompt.

### 1.5 Introspección de Base de Datos (`datia_schema.py`)
Componente crítico para la seguridad y visibilidad de datos.
- **Regla de Oro**: La introspección de esquemas y tablas SIEMPRE debe realizarse sobre la conexión **PostgreSQL** (`connections['analytics']`), NUNCA sobre la base de datos por defecto (SQLite).
- **Tablas Autorizadas**: Solo expone tablas que comiencen por `datiadb_` (case-insensitive para compatibilidad).
- **Fuente de Verdad**: Las tablas sincronizadas (Auto Entreno) residen exclusivamente en Postgres.
- **Infraestructura**:
  - Modelos alojados en `F:\ollama_models` (Variable `OLLAMA_MODELS`).
  - Modelo principal instalado: `deepseek-r1:14b`.

2. Arquitectura Frontend (Interfaz)
-----------------------------------
Gestionado por `datia/static/js/dashboard/ia.js` y `tab_ia.html`.

### 2.1 Flujo de Chat (`askAI`)
- **Entrada**: `div#ai-input`. Soporta comandos slash como `/reset`.
- **Loader**: Animación "Brain Experience" con pasos (`Conectando`, `Explorando`, `Validando`).
- **Renderizado**: `renderAiResponse()`.
  - **Badge AI**: Marca respuestas generadas automáticamente.
  - **SQL Debug**: Si el modo developer está activo, muestra el SQL crudo.
  - **Tipos de Respuesta**:
    - `report`: Gráficos + KPIs + Tabla.
    - `table`: Tabla simple.
    - `text`: Texto plano.

### 2.2 Deep Dive (`triggerDeepDive`)
Funcionalidad "Analizar más".
- **Disparador**: Botón en informes existentes.
- **Lógica**: Envía una nueva consulta al backend inyectando un prompt de análisis avanzado ("Focus ONLY on distribution...").
- **UI**: Renderiza gráficos adicionales (Pareto, Distribución de Margen) sin repetir los datos base.

### 2.3 Entrenamiento Manual
Si la Query_builder no sabe responder el frontend ofrece un botón para "Enriquecer conocimiento" esto dispara el modo entranmiento para que la IA busdque dentro de postgres schema datiadb_Nombredelatabla y pueda entrenar el repositorio de donde se nutre query_builder. Si la respuesta de query_builder no es la esperaba el ciclo vuelve a empezar. Si una consulta creada en el repositorio de query_builder no es acepta por el usuario esta se debera eliminar. La IA nunca puede devolver un sql al usario, solo query_bulder puede hacerlo. 

3. Modelos de Datos Asociados
-----------------------------
- **MetricsEmbeddings**: Almacena vectores de FAQs y esquemas.
- BusinessContext: Almacena el conocimiento estático de la empresa (ver `Auto entreno.md`).

Implementación de un sistema de generación de "Dossiers Ejecutivos" cuando el usuario solicite un resumen general (keywords: "Resumen", "Dossier", "Análisis", "Cómo vamos").

#### 4.1 Router & Intent
- **Detector**: Ampliar `IntentRouter` para capturar intenciones de reporte global.
- **Keywords**: "Resumen", "Dossier", "Análisis", "Resultado", "Datos", "Informe", "Cómo vamos", "Qué pasó", "Cuéntame", "Dime", "Explica".

#### 4.2 Estructura del Informe (Payload)
El backend debe orquestar múltiples consultas en paralelo y devolver un objeto JSON estructurado:
1.  **Pedidos (Compra/Venta)**:
    - Listado pedidos activos + Estado + Fechas (Creación/Entrega).
2.  **Albaranes**:
    - Volumen por tipo, Tiempos de proceso, Incidencias.
3.  **Finanzas (Ventas/Compras)**:
    - Comparativa Año Actual vs Anterior (Mensual).
    - Totales Acumulados + Variación %.
    - Evolución de Márgenes (Bruto/Neto).
4.  **Rankings**:
    - Top 10 Clientes (Volumen).
    - Top 10 Proveedores (Compra).
    - Top 20 Artículos (Rotación).
5.  **Indicadores**:
    - Tendencias (Semanal/Mensual).
    - Estacionalidad y Desviaciones.

#### 4.3 Visualización (Frontend)
- **Vista**: Nuevo tipo de respuesta `report` en `ia.js`.
- **Componentes**:
    - Gráficos comparativos (Bar/Line Mix).
    - Tablas resumen compactas.
    - Tarjetas de "Insights" (Alertas/Highlights).
- **Exportabilidad**: Botón para generar PDF/HTML limpio para impresión.
